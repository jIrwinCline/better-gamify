# Working on Better Gamify

Better Gamify pairs small gamification components with implementation skills that adapt
them to an existing product. Available components are Action Credits, Reward
Button, XP & Level Meter, and Milestone Celebration.

- `components/` contains reusable browser components. Keep these independent of
  the showcase and of any particular application backend.
- `skills/` contains the implementation instructions and their supporting files.
  Keep each pattern's skill, examples, and documentation consistent.
- `site/` is the static showcase. Demo state must be identified as simulated;
  browser clicks and timers never establish real completion or award credits.
- `docs/` explains integration. Document only behavior the component implements.
- `dist/` is generated by `npm run build`; edit source files instead.

Preserve the dependency-free setup unless a change has a clear need for a
dependency. Reuse the current tokens, accessible controls, and responsive layout.
Do not add speculative patterns to the shipped catalog.

For Action Credits, the host server owns eligibility, verification, reward
amounts, beneficiary identity, and durable award deduplication. The UI requests an
action and renders supplied state. Never turn a demonstration into a client-side
credit ledger or mark an external action verified merely because its link opened.

Run `npm test` and `npm run build` for relevant changes. For UI changes, inspect
the showcase at narrow and wide widths, including keyboard interaction and
pending/error states. Report any check that could not be run.
