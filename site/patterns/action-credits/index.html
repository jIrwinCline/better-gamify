PATTERN 001 / ONBOARDING & ACTIVATION

Action Credits:
SaaS onboarding rewards.

Help people reach their first useful result with an optional checklist of actions that earn product credits.

Action Credits combines a reusable interface with an implementation skill. The component presents actions and progress. The skill helps an agent choose suitable rewards, fit your existing design, and connect verified completion to your credit system.

Try three interactive examples ↗

How actions for credits work

  1. Choose a meaningful action. Creating a first project, exporting a result, or welcoming a teammate can help someone get more value from your app.
  2. Explain the reward up front. Show what must happen, how many credits it earns, and any relevant conditions before the person starts.
  3. Verify completion. A trusted application event or supported provider check establishes what happened. Opening a link alone does not prove completion.
  4. Award once. Your server records the reward and returns the updated state. The interface shows the confirmed credit award.

Three layouts, the same reward flow

  • Reward cards: a spacious welcome screen with clear actions and reward amounts.
  • Onboarding checklist: compact rows that sit naturally beside an existing setup flow.
  • Compact panel: a smaller bonus-credit surface for an account page or dashboard.

All three layouts support light and dark themes, keyboard interaction, pending and awarded states, and an immediate Continue action. Styling is controlled through CSS variables so the component can adapt to your app.

What to reward

Start with a small set of actions that have value for both the user and the product. A first successful export is more meaningful than clicking an export button. An accepted teammate invitation is more useful than sending a batch of invitations. Keep existing signup and referral bonuses in view so the same action does not earn the same reward twice.

Social follows, stars, subscriptions, and shares need a current check of the destination platform's rules and verification capabilities. They are candidates, not mandatory tasks. The implementation skill includes an action-selection guide and alternatives when a social incentive is unsuitable.

Install the component

Download action-credits.js and import it as an ES module. Place <action-credits></action-credits> in your page. Populate its actions property with server-provided state and respond to its action-request event in your application.

The component has no dependencies and does not issue credits, call a provider, or store an authoritative balance. You own the source and the integration. Read the full component API.

Install the implementation skill

Download the Action Credits skill, extract it, and copy the entire action-credits folder into ~/.codex/skills/. Keep any existing version until you have compared it. Open your application project in a new chat and invoke $action-credits.

The skill guides product discovery, action selection, reward economics, UI integration, server verification, duplicate prevention, and relevant testing. It asks for missing product decisions while continuing independent implementation work.

Keep the experience optional

Users should be able to continue into the product, skip an action, and return to their progress. A delayed provider check should never trap someone in onboarding. Show pending and retry states honestly, and reserve celebration for a confirmed award.

The gallery uses simulated actions and demo credits. Reward amounts are illustrative, not recommended pricing. Production awards belong in your application's authenticated credit system.
